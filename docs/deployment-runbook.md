# Развёртывание: порядок действий (A4)

Тестовая сеть BNB, chain id 97. Боевая сеть — только после внешнего аудита (A5).

## До начала

Требуется решение по ключам. Пять ролей — пять разных ключей, ни один не совмещает выпуск и
списание долей:

| Переменная | Роль | Требование |
|---|---|---|
| `ADMIN_ADDRESS` | `DEFAULT_ADMIN_ROLE` | мультисиг. В боевой сети — обязательно, в тестовой допустим обычный адрес |
| `MINTER_ADDRESS` | `MINTER_ROLE` | кастоди или операционный ключ выпуска |
| `COMPLIANCE_ADDRESS` | `COMPLIANCE_ROLE` | комплаенс: заморозка, сжигание, принудительный перевод |
| `PAUSER_ADDRESS` | `PAUSER_ROLE` | приостановка операций |
| `ORACLE_ADDRESS` | `ORACLE_ROLE` | передача данных об обеспечении |
| `ALLOWLIST_AGENT_ADDRESS` | агент белого списка | сервисный ключ бэкенда, которым работает `EvmAllowlistGateway` |

Деплойер — отдельный ключ, по итогам развёртывания он не сохраняет никаких прав.

Раскладка проверена в EVM тестами [`test/Deploy.t.sol`](../test/Deploy.t.sol) — прогоняются в CI до
того, как какой-либо ключ коснётся живой сети.

## Порядок

1. Подготовить ключ деплойера. Приватный ключ в `.env` не кладём:

   ```bash
   cast wallet import atria-deployer --interactive
   ```

2. Заполнить `.env` по образцу [`.env.example`](../.env.example): адреса ролей, параметры выпуска
   (`TOKEN_NAME`, `TOKEN_SYMBOL`, `TOKEN_MAX_SUPPLY` — размер зарегистрированного выпуска в штуках,
   `PROPERTY_ID` — идентификатор объекта), RPC и ключ верификации.

   `PROPERTY_ID` берётся из бэкенда, а не набирается руками:

   ```bash
   curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
     "$API/api/v1/properties/$PROPERTY_GUID/token-contract" | jq -r .propertyIdBytes32
   ```

   Это `Property.Id` (GUID), выровненный влево в 32-байтовом слове и добитый нулями справа.
   Конструктор записывает его неизменяемо и отклоняет пустое значение, скрипт развёртывания —
   ещё и значение неправильной формы (`0x…01`, хеш, что угодно придуманное на месте). Бэкенд при
   привязке контракта спрашивает у него `propertyId()` и отказывается связывать объект с
   контрактом, который называет другой выпуск. Ошибка здесь чинится только повторным
   развёртыванием.

3. Пополнить адрес деплойера тестовым BNB: <https://www.bnbchain.org/en/testnet-faucet>.

4. Сухой прогон без отправки транзакций:

   ```bash
   forge script script/Deploy.s.sol:Deploy --rpc-url bsc_testnet --account atria-deployer
   ```

5. Развёртывание с верификацией исходников:

   ```bash
   forge script script/Deploy.s.sol:Deploy --rpc-url bsc_testnet --account atria-deployer \
     --broadcast --verify
   ```

   Разворачиваются `IdentityRegistry`, `Allowlist` и токен; выдаются роли; владение белым списком
   переходит админу, агентом остаётся сервисный ключ бэкенда; деплойер отзывает у себя
   `DEFAULT_ADMIN_ROLE`.

6. Проверить результат по состоянию сети, а не по логу скрипта:

   ```bash
   TOKEN_ADDRESS=0x... DEPLOYER_ADDRESS=0x... \
     forge script script/CheckDeployment.s.sol:CheckDeployment --rpc-url bsc_testnet
   ```

   Скрипт падает на первой же несостыковке: неверная роль, деплойер с остатком прав, несовпадение
   размера выпуска или `propertyId`.

7. Занести адреса:
   - в объект через `PUT /api/v1/properties/{id}/token-contract` (адрес контракта, тег сети, кошелёк
     эмитента) — это источник истины. Бэкенд сверяет `propertyId()` контракта с объектом и
     возвращает 409, если контракт принадлежит другому выпуску или развёрнут с заглушкой;
   - в справочный перечень [`deployments/README.md`](../deployments/README.md).

8. Проверить связку с бэкендом: адрес попадает в белый список через `AllowlistAdd`, и только после
   этого проходит минт. Минт на адрес не из белого списка контракт откатывает сам.

## Чего не делать

- Не разворачивать боевой контракт до аудита: исправить развёрнутый контракт нельзя, потребуется
  новый контракт и перенос держателей.
- Не выпускать доли одного объекта более чем в одной сети.
- Не хранить адрес контракта в конфигурации приложения — только на объекте.
- Не оставлять `DEFAULT_ADMIN_ROLE` на ключе деплойера «на время».
- Не разворачивать с временным `PROPERTY_ID` «чтобы потом заменить»: значение неизменяемо, заменяется
  только контракт целиком.
