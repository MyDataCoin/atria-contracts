# Развёрнутые адреса

Справочный перечень. **Источник истины — объект в бэкенде** (`Property.TokenContractAddress`,
`Property.TokenChain`, `Property.IssuerWalletAddress`, заполняются через `Property.SetTokenContract`).
Адреса контрактов не хранятся в конфигурации приложения.

Одна сеть на один выпуск: у каждого объекта ровно один контракт токена и ровно один адрес.

### ATRP-T1 — устарел, для прогона непригоден

Оставлен в перечне как история. Две причины непригодности:

`PROPERTY_ID` — заглушка `0x…01`, то есть контракт не называет никакого выпуска. Привязать его к
объекту нельзя: бэкенд сверяет `propertyId()` с `Property.Id` и вернёт 409. Значение неизменяемо,
поэтому и потребовался новый контракт; скрипт развёртывания заглушку больше не пропускает.

`maxSupply = 1 000 000`. Прежнее замечание в этом файле утверждало, что `decimals = 0` — это
сборка «до перехода на `decimals = 2`» и потому минт 10 долей выпустил бы 1000. Замечание
устарело: переход на дробные доли отменён, `TokenAmount.Scale` вернулся к 0, и `decimals = 0`
теперь верное значение — оно же у действующего ATRP-BR1.

Раскладка ключей ATRP-BR1 проверена `CheckDeployment` по состоянию сети — 20 проверок, включая то,
что деплойер не сохранил ни одной роли и не остался агентом белого списка.
