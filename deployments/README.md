# Развёрнутые адреса

Справочный перечень. **Источник истины — объект в бэкенде** (`Property.TokenContractAddress`,
`Property.TokenChain`, `Property.IssuerWalletAddress`, заполняются через `Property.SetTokenContract`).
Адреса контрактов не хранятся в конфигурации приложения.

Одна сеть на один выпуск: у каждого объекта ровно один контракт токена и ровно один адрес.

Параметры выпуска: `decimals = 0`, `maxSupply = 1 000 000`, выпущено 0, операции не приостановлены.
**`decimals = 0` — это сборка до перехода на `decimals = 2`.** Бэкенд отправляет доли в минорных
единицах с масштабом `TokenAmount.Scale = 2`, поэтому против этого контракта минт 10 долей выпустил бы
1000. Контракт непригоден для прогона с бэкендом.
`PROPERTY_ID` — заглушка `0x…01`, то есть контракт не называет никакого выпуска. **Привязать его к
объекту нельзя:** бэкенд сверяет `propertyId()` с `Property.Id` и вернёт 409. Значение неизменяемо,
поэтому для прогона нужен новый контракт, развёрнутый с `propertyIdBytes32` из бэкенда — скрипт
развёртывания заглушку больше не пропускает.

Раскладка ключей проверена `CheckDeployment` по состоянию сети — 20 проверок, включая то, что
деплойер не сохранил ни одной роли и не остался агентом белого списка.
